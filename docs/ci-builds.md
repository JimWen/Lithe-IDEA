# macOS CI builds and test downloads

The macOS package lane uploads complete test packages when product changes select
that lane. Open the workflow run's **Summary** and follow **macOS test download**,
or use the run's **Artifacts** list. This fork ships macOS only; its packages do
not add JDK/JDTLS, Maven/Spring or Linux.do resources.

- Pull requests build separate Apple Silicon (`arm64`) and Intel (`x86_64`) DMGs.
  The jobs can run concurrently when both runners are available.
- Main pushes and manual runs verify the default universal assembly and its
  negative checks, then assemble a distributable DMG using the compiled outputs.
- The lane verifies code signatures, required executable architectures, the DMG
  and its SHA-256 checksum. Test apps are ad-hoc signed.
- Each upload contains the DMG and checksum, uses compression level zero, and is
  retained for 14 days. GitHub sign-in is required to download it.

The summary records the checked-out revision. Pull requests normally use GitHub's
merge-test revision. An artifact can appear before other jobs finish; check the
**macOS CI gate** for the combined result. `fail-fast: false` lets the other
architecture finish even if one fails, while the failed architecture still fails
the gate. Documentation-only changes can skip packaging. A manual CI run selects
complete validation and packaging.

The GitHub CLI can download a run's packages from the current repository:

```sh
gh run download <run-id> --pattern 'Lithe-macos-*'
```

Preview jobs also expose their architecture-specific artifact links before the
rolling Release publishes. Use the current preview workflow's tag and version
for published downloads; the source revision in its summary identifies the build.

## Compilation caches

The package CI and preview workflows cache Cargo fingerprints, build-script
outputs and dependency outputs under both `rust/target/macos` (Core) and
`rust/target` (database helpers). Keys include runner and target architecture,
Rust compiler, Xcode, SDK and macOS versions, deployment target, Rust flags,
dependency manifests and build scripts. An architecture-specific job can fall
back to a compatible universal cache. Final executables are regenerated by Cargo.

A failed cache restore discards partial compilation output and falls back to the
existing verified crate archive cache. SwiftPM repository caches keep their
integrity validation; Swift compilation products are not cached. The cache action
retains no Java download inputs or preparation steps.

These changes preserve upstream `a92d3b47`'s generic packaging and cache behavior.
Their integration does not establish a measured build-time improvement: compare
actual cold and warm fork runs before making that claim. Queue delays and runner
availability are separate from compilation time. Candidate preparation did not
execute a remote CI workflow or publish artifacts.
